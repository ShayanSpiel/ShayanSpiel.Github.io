{% include components/section-head.html tag='Service' title='Find what is making your agent harness brittle' sub='For existing agent systems that are difficult to reason about, test, maintain, or scale.' %}
Buyer stage

System is live but fragile

Your agent is in production or near it. The team can ship changes but nobody is confident about what will break. Engineering time is consumed by unpredictable failures rather than feature work.

Main symptoms

You know these signs

Small changes break unrelated behavior. Nobody knows the source of truth for prompts, tools, or roles. Context grows without policy. Memory behavior is unpredictable. Tests only check final outputs.

Inputs required

What I need from you

Access to the codebase or harness configuration, traces or logs from recent failures, prompt definitions, tool schemas, current tests, and a candid conversation with the team about pain points.

What is not included

Boundaries

No production code changes. No deployment. No full system rewrite. The audit identifies structural problems and recommends a sequence of changes, but your team or an implementation vendor performs the work.

{% include components/section-head.html tag='Symptoms' title='Common patterns of a brittle harness' sub='' %}
Pattern

Agent roles overlap

Multiple agents or subagents can perform the same operation, creating conflicts and unpredictable routing.

Pattern

Prompts contain business logic

Rules, permissions, and approval criteria are embedded in system prompts instead of defined in structured configuration.

Pattern

State ownership is unclear

Multiple components read and write the same state without a defined owner, causing drift and conflicts.

Pattern

Context grows without policy

Every turn adds more context. No eviction strategy exists. Token limits are hit unpredictably.

Pattern

Memory behavior is unpredictable

What the agent remembers across sessions depends on implicit rules rather than explicit design.

Pattern

Tool permissions are broad

Tools have access beyond what the agent needs. Permission boundaries are not enforced at the tool level.

Pattern

Subagents lack clear boundaries

Subagents can access parent state, override decisions, or operate outside their intended scope.

Pattern

Small changes break unrelated behavior

A prompt change in one area causes failures in another. No isolation boundaries exist.

Pattern

Tests only check final outputs

No trajectory, tool-call, or intermediate-state tests exist. Passing end-to-end tests can mask serious structural problems.

{% include components/section-head.html tag='Audit dimensions' title='What I examine' sub='Seventeen dimensions of harness health, assessed against structural best practices.' %}
Dimension

Workflow decomposition

How the operational workflow is split into agent steps and whether the boundaries match reality.

Dimension

Graph and node responsibility

Whether each node has a single clear responsibility and how nodes communicate.

Dimension

Role boundaries

Whether agent roles overlap, conflict, or leave gaps.

Dimension

State ownership

Who owns each piece of state and how conflicts are resolved.

Dimension

Prompt hierarchy

How prompts are structured, versioned, and which contain logic that belongs elsewhere.

Dimension

Context construction

What enters context, in what order, and whether injection, truncation, or overflow is handled.

Dimension

Memory policy

What is stored, retrieved, and evicted across sessions and whether the policy is explicit.

Dimension

Tool permissions

Scope, access control, and safety boundaries for every tool connected to the agent.

Dimension

Human approval points

Where humans must approve, review, or intervene and whether those gates are enforced.

Dimension

Failure recovery

How the system handles errors, retries, and degraded states and whether recovery is deterministic.

Dimension

Observability

Whether traces, logs, and metrics capture enough information to debug failures.

Dimension

Evals

What is measured, what is not, and whether evals cover trajectory or only final output.

Dimension

Cost and caching

Whether prompt caching is used effectively, token waste exists, or cost grows unbounded.

Dimension

Configuration

How the system is configured and whether configuration changes require code changes.

Dimension

Separation of concerns

Whether prompts, logic, state, and configuration are cleanly separated or tangled together.

Dimension

Duplicated policy

Whether the same rules exist in multiple places and whether they stay in sync.

Dimension

Documentation drift

Whether architecture documentation matches the running system and where it diverges.
