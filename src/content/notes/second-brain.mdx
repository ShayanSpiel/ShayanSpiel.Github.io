<section class='section'>
  <SectionHead tag='The architecture' title='The 4-File Architecture' sub='The content engine is 4 files. That is the whole system. If your system is 40 files, you have a system, not a tool.' />

  ```
~/.config/opencode/
├── opencode.jsonc          (registers the skill + command)
├── .env                    (X / LinkedIn API keys, chmod 600)
├── skill/geogent-content/
│   └── SKILL.md            (the system spec, auto-injected into every session)
└── command/
    └── post.md             (the /post slash command)
```

  <ProseCenter text='The rest lives in the vault. At the end of a session, I run /post. The slash command reads the most recent session log, reads the 10 strategy pages, and drafts 2-3 posts. The drafts land in content/queue/. I open the folder, pick one, post it.' />

  <ProseCenter text='The system drafts. I decide. The LLM is the writer. I am the editor. The boundary is the queue.' />
</section>

<hr class='divider' />

<section class='section'>
  <SectionHead tag='The mechanism' title='The Decision Tree' sub='The hardest part of should I post this is not the writing. It is the type. Is this a ship post? A lesson post? A decision post?' />

  ```
Did something ship?
  YES → Ship Announcement
  NO  → Was there a decision?
          YES → Decision Post
          NO  → Was there a lesson?
                  YES → Today I Learned
                  NO  → Milestone?
                          YES → Vision / Big Picture
                          NO  → Dev Log
```

  <ProseCenter text='The tree is a 7-node decision procedure. It takes the session log as input and outputs a single type. The type determines the structure. The structure determines the voice. The voice determines the post.' />

  <ProseCenter text='This is the pillar method in one sentence: one piece of work becomes many pieces of content, all sampled from one source.' />
</section>

<section class='section'>
  <SectionHead tag='Try it' title='The 24-Hour Build' sub='The system is open-source. The 4 files are 4 markdown files. The whole thing is reproducible in an afternoon.' />

  <div class='step-list'>
    <div class='step-item'>
      <div class='step-num'>01</div>
      <div class='step-body'>
        <strong>Hour 1: the vault</strong>
        Set up an Obsidian vault. 4 folders: entities/, concepts/, summaries/, raw/. Write 5 pages about your work. Link with wikilinks. The LLM needs the graph.
      </div>
    </div>
    <div class='step-item'>
      <div class='step-num'>02</div>
      <div class='step-body'>
        <strong>Hour 2: the strategy pages</strong>
        Write 4 pages: content strategy, tone of voice, content types, ground vision. These are the pages that define what the system posts. If you cannot write the spec, the LLM cannot draft.
      </div>
    </div>
    <div class='step-item'>
      <div class='step-num'>03</div>
      <div class='step-body'>
        <strong>Hour 3: the slash command</strong>
        Install opencode. Create a SKILL.md. Create a /post command. Wire it to read the vault, read the strategy pages, run the decision tree, output drafts to a queue folder. Test on a fake session.
      </div>
    </div>
    <div class='step-item'>
      <div class='step-num'>04</div>
      <div class='step-body'>
        <strong>Hour 4: the first real post</strong>
        Do a real work session. At the end, run /post. Read the drafts. Run the standalone quality test. Pick the best. Post it. The system has now produced its first post.
      </div>
    </div>
  </div>
